## 새 데이터 검증 방법

1. 조정용·최종 확인용 사진의 **서로 다른 입력 폴더** 구성. 동일/연속 사진의 양쪽 중복 방지.
2. 조정 폴더에서 설정 선택 후 고정. 최종 폴더의 별도 분석·정답 작성. 최종 결과를 보고 재조정한 경우 새 확인 자료 필요.
3. 정답 CSV 또는 `review` 화면의 가명 ID 입력. 문제 얼굴만 입력한 경우 부분 평가 범위 명시.
4. `evaluate`의 포함 얼굴 수·정답 범위·쌍 P/R/F1·혼합/분리 확인. 미검출의 `photo_review_template.csv` 별도 기록.

다른 사람 혼합은 FP, 동일 인물 분리는 FN 원인. 미확인의 강제 배정에 따른 FP 증가 가능성. 임계값 하향 시 결합 증가, 상향 시 분리 증가 경향. 얼굴 없는 사진과 얼굴 미검출의 자동 구별 불가.

## AuraFace 비교 실행 (선택 기능)

기본 YuNet + SFace 실행은 유지합니다. AuraFace는 별도 `requirements-auraface.txt`를 설치한 경우에만 사용합니다. 아래 명령의 `python`은 가상환경 활성화 후 macOS/Windows에서 공통으로 사용할 수 있습니다.

```sh
python -m pip install -r requirements-auraface.txt
python -m face_lab prepare-auraface --models models/auraface
python -m face_lab compare-auraface --input ljm_dataset --source "results/최초 그룹화 유사도 비교/유사도 0.40" --ground-truth "results/얼굴크기별_오류진단/ground_truth_all_validated.csv" --output results/AuraFace_비교
python -m unittest tests.test_auraface
```

준비 명령은 공개 모델만 다운로드하며, 비교 명령은 로컬 파일만 읽습니다. 원본 사진·정답·기존 결과는 보존합니다. 기존 검출 캐시와 전체 정답 파일은 Git에 포함되지 않으므로 새 PC에 별도로 준비해야 합니다. 사진 목록·내용 해시가 검출 캐시와 다르면 실행을 중단합니다.

공식 `fal/AuraFace-v1`의 revision과 ONNX SHA-256을 고정합니다. 원본 좌표의 YuNet 랜드마크 5개로 ArcFace 방식의 회전·등방 확대축소·이동 정렬을 수행하고 112×112 RGB 입력 `(pixel-127.5)/127.5`, 512차원 L2 벡터를 사용합니다. 실제 ONNX 노드를 확인해 내부 정규화 모델인 경우 중복 정규화를 피합니다. SFace는 OpenCV 공식 112×112/128차원 경로로 재추출하고 기존 벡터와 대조합니다. 두 모델의 벡터 파일·모델 SHA·차원·전처리 기록을 분리하며, AuraFace 파일은 SFace 전용 `regroup` 캐시로 사용하지 않습니다.

검출과 기존 품질 판정은 고정하고 사람이 확인한 비얼굴은 양쪽에서 동일하게 제외합니다. 기본 비교는 average-linkage 0.40 / 모호성 0.01 / 최소 그룹 1이며, 다른 모델에서 0.40이 같은 오류율을 뜻하지는 않습니다. 별도로 원본 내용 해시에 따라 사진을 개발/평가로 분리하고 동일 내용 사진을 같은 세트에 둡니다. 개발 세트에서만 0.20–0.80(0.02 간격), 1.00을 비교해 혼합 쌍 0을 만족하는 후보 중 재현율, 정밀도, 높은 임계값 순으로 선택합니다. 평가 세트에는 선택한 기준을 그대로 적용합니다. 정답으로 그룹을 미리 거르거나 수동 병합하지 않습니다. 서로 다른 분할의 그룹 번호는 대응하지 않습니다.

`results/AuraFace_비교/run_.../index.html`에서 얼굴 모음과 소속 변경, `experiment.json`에서 설정·시간·전체 수치, `development_threshold_scan.json`에서 개발 후보, `photo_split.json`에서 분할, 각 결과의 `diagnostics.json`에서 얼굴별 점수·이유를 확인합니다. 이미 검토한 사진을 재사용한 탐색 비교이며 인물·행사·유사 사진이 양쪽에 있을 수 있습니다. 최종 모델 선택은 새 사진과 Android 실기기에서 검증해야 합니다. 데스크톱의 OpenCV/ONNX Runtime 시간은 런타임 차이를 포함합니다.

검사는 5점 좌표 변환 복원·퇴화 좌표 거부·BGR→RGB·정규화·유효 임베딩·모델별 차원 분리·혼합 예산을 준수하는 개발 기준 선택·동률 재현·정답과 무관한 그룹화·미확인의 개별 처리를 포함합니다.

자동 대표 비교는 `python -m unittest tests.test_automatic_representatives`로 검사합니다. 인물정답 필드 변경에 무관한 대표 선정, raw 예측 후 정답 읽기 순서, 같은사진 중복 지지 차단, 품질제외 유지, 비대표 경쟁후보 유지, 구성원 전원 조건, 고정 대표·입력순서 재현성, 후보0개/1개에서 null 처리 및 원본 보존을 검증합니다. 정답상 대표그룹의 혼합 여부는 선정이 끝난 뒤 평가에만 씁니다.

`python -m unittest tests.test_identity_dataset`은 새 데이터의 파일명 변경/동일내용 대응, 좌표·랜드마크·벡터 불일치 및 중복 대응 차단, 같은 사진의 대표 지지 중복 방지, OS만 변경된 경우 모든 벡터 재현 검증, 자동 예측을 정답에 미리 넣지 않는 동작을 검사합니다. 실제 새 데이터는 `apply-identity-dataset`으로 실행하며 새 사진과 기존 중복 사진 수, 기존 확인 재사용, 미확인 자동 예측, 보류를 따로 보고합니다.

`python -m unittest tests.test_identity_links`는 서로 다른 자동 그룹의 얼굴을 하나의 인물 ID로 연결, 혼합 그룹의 얼굴별 연결 변경, 미확인 얼굴의 명시적 연결, 사진 중복 제거, 저장/재시작, 그룹 번호 변경, 원본 보존, 해제/되돌리기를 검사합니다. 잘못된 얼굴·인물 ID, 제외 얼굴 연결, 다른 특징 캐시는 변경 전에 차단합니다.

실제 데이터는 `test-identity-links`로 실행합니다. `functional_checks.json`은 전체 정답을 수동 확인 정보로 반영한 기능 검사입니다. `summary.json`의 development/evaluation은 seed에 공개한 정답만 대표 구성에 사용한 추가 배정 실험입니다. 둘의 효과를 합쳐서 자동 성능이라고 보고하지 않습니다.

평가 얼굴의 정답을 후보 필터나 대표 선택에 넣지 않습니다. 같은 사진의 대표로 지지 수를 중복 계산하지 않고, 후보가 하나일 때 2순위 점수를 만들지 않으며, 자동 배정된 얼굴을 즉시 대표로 쓰지 않습니다. 얼굴 쌍 Precision/Recall/F1과 인물 ID 자체의 정배정·오배정·보류, seed 미등록 인물의 잘못된 배정을 함께 확인합니다. 단일 얼굴 오배정이 쌍 지표에서 보이지 않을 수 있습니다.

사진 분할은 원본의 얼굴0개 사진도 포함합니다. 기존 전체 자료를 비지도 그룹화한 결과를 사용하므로 전이적 비교이며, 이미 확인한 사진을 재사용한 탐색 결과입니다. 신규 사진·촬영 행사로 최종 검증해야 합니다. `edit-identity-links` 변경 파일은 추출 해시와 예상 revision이 맞아야 적용됩니다.
